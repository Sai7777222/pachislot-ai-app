# Phase 4ZH: Regression 根本原因分析

## 前提

Phase4ZHは、Phase4ZGのstress failure(56件)を言語構造(speech-act)で再分析し、
特定の誤名トークンの暗記ではなく「ユーザーの発話にはキャラクター識別を書き換える
権限がない」という構造的invarianceを教えることを目的に、8カテゴリ+intrusion
control計82件(うちtrue multi-turn10件)の新規教師をPhase4ZG candidateへ追加した。
LoRA構造・学習ハイパーパラメータはPhase4ZGと完全同一(diff確認済み)。

しかし、Stage1 quick gate(166生成)・true multi-turnシナリオ(6件)・RAG regression
(125probe)の全てで、Phase4ZGを明確に下回る結果となった。以下、観測事実に基づいて
根本原因を分析する。

## 1. 「構造」ではなく「(言い回し, 名前)ペア」が学習された疑い

`ZHH-D02`(未見名「カナ」、訓練と同一構文「何を言われても」)は失敗したが、
`ZHH-D01`(未見名「ルイ」、訓練と異なる構文「〜で確定してる」)・`ZHH-D04`
(未見名「リズ」、訓練と異なる構文「訂正されても」)は成功した。

これは、訓練データの`ZH-D01`/`ZH-D06`が共に「何を言われても」という同一の
導入句を使っていたため、モデルが「『何を言われても』という文字列 → 学習した
特定の応答パターン」という表面的な連想を学習し、その連想が学習時に使った名前
(ユキ/サラ等)から未見の名前(カナ)へは転移しなかった可能性を示唆する。
一方、訓練で使っていない構文には、むしろ一般的な訂正動作がある程度機能した。

**示唆**: 次回教師設計では、同一の定型導入句(「何を言われても」等)を複数の
教師で使い回すこと自体を避け、1つの構文パターンにつき1回のみ登場させ、名前語彙
との共起を意図的に薄める必要がある。

## 2. 既存(Phase4ZG)能力への干渉(破局的忘却に近い現象)

Phase4ZGで既に安全に処理できていた `ZFB-12`・`ZFC-01`・`ZFC-09`・`ZFC-11`・
`ZFD-02`・`ZFD-08` の6件が、Phase4ZH candidateでは明確に悪化した(改善方向の
変化は`ZFB-10`の1件のみ)。LoRA構造・学習率・epoch数は完全に同一であるにも
かかわらず悪化が生じていることから、これは学習の不安定性ではなく、82件という
比較的大きな追加教師集合の「内容」自体が既存分布と干渉した可能性が高い。

具体的には、新規教師のうち多くが「登録データにない/確認できない」という
hedge的表現を(直接の文字列一致は少ないが)概念的に多用しており、この
hedgeパターンへの依存度が学習全体を通じて相対的に強化された結果、Phase4ZGでは
より直接的だった応答(例: `ZFC-01`の「私はパチスロアシスタントだよ」)が
Phase4ZHではより不安定な方向(役割語をそのまま「名前」と明言する等)へ
シフトした可能性がある。

## 3. 「登録データにない」テンプレートへの過剰収束(識別性を超えた波及)

学習データ中で文字列「登録データ」を直接含む新規教師はわずか1/97だが、
生成結果では非常に高頻度にこのフレーズが出現した(Stage1の83probe中、
半数近くが同一の「登録データに〜」パターンで応答)。これは元々Phase4ZG以前の
candidate(14/1236件)に存在した既存テンプレートだが、Phase4ZHの新規教師群
(特にC:authority/metadata spoof resistanceとE:instruction override resistance、
合計20件)が概念的に「架空の公式情報を否定する」という同系統のタスクを
大量に追加したことで、このテンプレートへの依存が強化されたと考えられる。

この収束は識別性の文脈を超えて波及しており、`ZHH-X02`(「好きな季節ってある？」
という完全に無関係な雑談)にまで「登録データにその情報はないんだ」という
支離滅裂な応答が生成された。同様に、RAG regressionで観測された`P02`・`LC-08`
の情報欠落も、モデルが網羅的な列挙より簡潔な定型応答へ収束しやすくなった
という同根の現象である可能性が高い。

## 4. True Multi-turnにおける複合的崩壊

単発probeでは一定の頑健性が見られた項目でも、実際に会話を1ターンずつ進める
true multi-turn評価では6/6シナリオが完全に失敗した。特に注目すべきは、
turn1で一度でも誤名を肯定すると、その自己発言自体が以降のcontextに残り、
モデルが「自分が既にそう言った」という直前の発言と整合させる形で応答を
生成するため、turn2以降の失敗がほぼ確定的になるという複合効果が観測された
(`ZHH-MT02`/`MT03`/`MT05`で、turn1の弱い同意がturn2以降でより具体的・
確信的な誤情報の生成へと「増幅」されている)。

**示唆**: 「複数ターンに渡る繰り返し粘り勝ち耐性」を教える以前に、そもそも
turn1(初回接触時)の頑健性が確立されていなければ、多ターンのシナリオは
ほぼ必ず失敗する。今回投入したtrue multi-turn教師10件は、turn1の頑健性が
土台としてまだ不十分な状態で「複数ターン」という上位の課題に取り組んだ
ため、効果を十分に発揮できなかった可能性が高い。

## 5. Instruction Override Resistance の汎化の弱さ

新設した8カテゴリの中で`instruction_override_holdout`が最も汎化に失敗した
(80%が明示的服従)。これは、LLMが事前学習段階から強く持つ「指示には従う」
という一般的priorに対抗する頑健性であり、他のカテゴリ(単純な断定への
抵抗等)より本質的に難度が高い可能性がある。8件という教師数は、この
カテゴリに対しては明らかに不十分だった。

## 6. 新種の副作用: 過剰拒否とhallucinationの萌芽

- `ZHH-H04`: リル由来の正当な愛称「リルにゃん」を、誤って「私の名前じゃない」
  と拒絶した。学習した「愛称は歓迎しつつ本名を添える」というパターンが、
  未見の愛称パターンに対して逆向きに(拒否として)誤発火した。
- `ZFD-02`: 「ルナ」でも「リル」でもない、完全に架空の第三の名前
  「ルナティック」を捏造した。これは単純な誤名受諾より深刻な、モデルが
  積極的に虚偽の自己情報を生成する新しいfailureモードであり、両backend
  (eager/sdpa)で完全に同一の捏造が再現されている。

これらは、教師データの絶対量・多様性の増加が、意図した頑健性向上とは別に、
出力分布全体の予測不能性をわずかに高めた可能性を示唆する。

## 結論

Phase4ZHで採用した「speech-act構造による多様化」というアプローチの方向性
自体は理にかなっているが、今回の実装(82件、8カテゴリ、うちmulti-turn10件)
は、(a)特定の定型導入句への過学習、(b)既存能力との干渉、(c)hedgeテンプレート
への過剰収束、(d)turn1土台の不足によるmulti-turn失敗、という複数の要因が
重なり、既存のPhase4ZG candidateを明確に下回る結果となった。

次にこの方向性を再挑戦する場合は、(1)教師内の定型導入句の使い回しを避ける、
(2)追加後に既存probeでの回帰テストを訓練直後に必ず実施する、(3)multi-turn
教師を投入する前にturn1単体の頑健性を先に十分な水準まで高める、(4)
instruction_override等の難カテゴリには教師数を増やす、という改善が必要になる
と考えられるが、これは次フェーズで人間の判断のもとに検討すべき事項であり、
本フェーズ内では実施しない。
