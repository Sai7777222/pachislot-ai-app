# Phase 4H-2: Q3型「重要情報の省略」問題の分析

## 対象
Phase 4E/4Gで一貫して問題になっている構造化DB/RAG評価の Q3（「天井は？」）。

## RAGコンテキストの実際の構造
```
【対象機種】
スマスロ ミリオンゴッド-神々の軌跡-（パチスロ） 設定判別・天井・ゾーン・解析・打ち方・ヤメ時
このセクション以下の情報はすべて上記の機種に関するものです。他の機種の名称を補完したり、機種名を推測したりしないでください。

【構造化データ（数値・確率・設定差・天井・示唆など）】
このセクションの数値は必ず原文表記のまま回答に使ってください。計算し直したり丸めたりしないでください。

- [天井/設定変更時・天井ゲーム数振り分け] ゲーム数=510G: 15.2%
- [天井/設定変更時・天井ゲーム数振り分け] ゲーム数=1000G: 20.3%

- [天井/到達天井時のループストック振り分け] ループストック=0.01: 16.7%
- [天井/到達天井時のループストック振り分け] ループストック=0.25: 16.7%
- [天井/到達天井時のループストック振り分け] ループストック=0.5: 16.7%

【関連する解説文章】

天井ゲーム数は3種類あって、抽選で決定。また、天井到達時はループストック抽選がおこなわれ、約33%でZ-ZONEが付与される。
```

質問「天井は？」に**直接関係する情報**は、構造化データの8行のうち全8行（天井ゲーム数3種の確率＋ループストック5種の確率）と、解説文の「◆天井解説」1件のみ。残り5件の解説文（前兆・裏天国・天空の扉・中パターン・出目示唆）は明確に無関係。

## 回答比較

| 条件 | 回答 | 含まれる情報 |
|---|---|---|
| A(base) | 天井ゲーム数3種の値と確率(15.2%/20.3%/64.5%)、ループストック抽選とZ-ZONE付与確率(33.2%) | 構造化データの主要項目をほぼ網羅 |
| B(v1) | 天井ゲーム数3種の値(510G/1000G/1480G)、抽選で決まる旨 | 具体的な値のみ、確率(%)は全省略 |
| C(v2) | 天井ゲーム数は3種類、抽選で決定、のみ | 具体的な値も確率も全省略。**v1よりさらに簡潔化** |

## 何が省略されたか
- v1: 構造化データの数値（15.2%/20.3%/64.5%、ループストック関連の33.2%）を全て省略。ゲーム数(510G/1000G/1480G)のみ保持。
- v2: 上記に加え、ゲーム数の具体値(510G/1000G/1480G)まで省略。「3種類ある」という個数情報のみ残った。

## なぜPhase 4FのHカテゴリが実RAG形式に十分転移しなかったか（分析）

1. **形式の乖離**: Hカテゴリの学習例は `参照情報：fact1、fact2、fact3\n質問` という単一行・フラットな形式だった。実際のRAGコンテキストは
   - 【対象機種】ヘッダー
   - 「数値は原文表記のまま」という注記
   - `- [カテゴリラベル] 項目=値: 確率%` という構造化箇条書き（8行）
   - `◆ 見出し（出典カテゴリ: xxx）` という解説文セクション（6件、うち1件のみ関連）
   という、複数セクション・複数ソースからなる長い文書。この構造そのものを扱う訓練例がHカテゴリには存在しなかった。

2. **「関連情報の取捨選択」が学習されていない**: Hカテゴリの16例は全て「参照情報＝すべて質問に関連」という設計だった（Phase 4Fの人間レビューで「質問と関係の薄い情報は省略してよい」という方針に修正済みだが、それでも「関連ソースの中から一部を選ぶ」訓練であり、「6つの解説文セクションの中から1つだけ関連するものを選び、かつその1つを咀嚼して構造化データの数値も合わせて答える」という複合的な取捨選択は訓練していない）。

3. **プローズ文への引きずられ**: 実際のRAGコンテキストには「◆天井解説」という、既に簡潔にまとめられた解説文が含まれている。v1/v2はいずれもこの解説文の文体・情報量に強く引っ張られて回答しており、その上流にある構造化データの数値（15.2%等）まで遡って参照できていない可能性が高い。v2はこの解説文をさらに圧縮した形になっており、「解説文を要約する」方向にモデルが最適化されている兆候がある。

4. **RカテゴリとHカテゴリの目的の綱引き**: Phase 4Fで同時に追加したRカテゴリ（反復抑制、「1回答内で各事実を一度だけ簡潔に」）は、Hカテゴリ（「関連する複数情報を省略しない」）と部分的に緊張関係にある。v2がv1よりもさらに簡潔になった事実は、この2つの目的のうちRカテゴリ的な「簡潔さ」への最適化が強く効いてしまった可能性を示唆する。

## Phase 4H-3への設計方針
上記の分析から、以下を満たす追加学習データが必要と判断する。

- 実際のRAGコンテキストと同じ形式（ヘッダー＋構造化箇条書き＋複数の出典ラベル付き解説文セクション）を模した架空データを使う。
- 質問に**直接関連する**構造化データ・解説文は複数（数値を含む）まとめて回答し、**関連しない**解説文セクションは無視する、という「取捨選択」を明示的に訓練する。
- 「全部答える」ではなく「質問の対象に直接関連する情報だけを省略しない」という原則を、より複雑な文書形式の中で再現する。
- Rカテゴリ的な簡潔さ（同一事実の反復を避ける、不要な感想を付けない）は維持しつつ、関連する複数の数値情報は残す、というバランスを示す例にする。
